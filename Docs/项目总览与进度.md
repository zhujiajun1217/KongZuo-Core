## 四人团队协作约定

先由团队在下表补上实际成员姓名，再通过 GitHub PR 认领任务。此表不预设或替团队决定当前负责人。

| 职能 | 成员 | 主要改动范围 | 集成注意事项 |
|---|---|---|---|
| 程序/主线集成 | 待团队填写 | `Assets/KongZuo/Scripts/`、`Assets/KongZuo/Editor/`、构建与主线逻辑 | 协调主场景合并和 Unity 回归 |
| 场景/关卡 | 待团队填写 | `Assets/KongZuo/Scenes/`、关卡摆放、碰撞和触发器 | 同一 `.unity` 场景指定唯一编辑负责人 |
| 建模/美术 | 待团队填写 | `Assets/KongZuo/Art/`、`Assets/KongZuo/ZhaiModel/`、模型/材质/Prefab | 保留 `.meta`；尽量提交独立资源，不同时改主场景 |
| 剧情/谜题/音频 | 待团队填写 | 剧情与谜题内容、`Assets/KongZuo/LMLWeek4/` 音频演示及验收 | 正式主线接入前与程序及场景负责人确认接口 |

每次 PR 建议说明：改了什么、影响哪个版本/场景、如何在 Unity 中验证、验证结果及未完成项。合并后由负责人更新本页对应状态和验收记录；未测试项明确写“待验证”，不要写成“已完成”。

## 仓库整理规则

- 当前主线、LMLWeek4、V0.3 和已有 ZIP 归档均保留；它们有不同用途，不因为目录旧或重叠就直接删除。
- 暂不移动 Unity `Assets/` 中的文件。场景、Prefab、材质和脚本之间通过 `.meta` GUID 互相引用；整理目录须由熟悉 Unity 的负责人评估并在编辑器内完成。
- 新增或移动 Unity 资源时，把对应 `.meta` 一起纳入 Git；不要手工重建 GUID。
- 不提交 Unity 缓存和个人构建输出；详见根目录 `.gitignore`。

# 《空座》V0.3 剧情衔接包 · 导入和试玩

**适用**：Unity 6000.3.26f1、Windows、Universal 3D/URP；同时兼容启用新 Input System / Legacy Input Manager 的项目。

**来源**：`《空座》序章与前两章剧情剧本_V0.3_30-40分钟版(1).docx`。以 V0.3 的人物、道具、时间、信息边界和章节结尾为准。

## 这个补丁做了什么

1. 添加三套**完全独立的灰盒测试场景**：序章《拆楼前夜》、第一章《座》、第二章《人》。
2. 把旧 P0 示例中的“座次复原谜题”改成 V0.3 要求的**照片对景与遗物点交关联**（正式美术对景尚需替换灰盒阶段提示实现）。
3. 增加镜框剧照／顾兰生活照／购票凭证／争执残响／许承山纸条／旧戏箱登记／东侧门短残响与拍照后收束。
4. 保留真实与假设的边界：**不提前公开**锁门者、火源、顾兰藏票经过、沈芸最终去向、B1返场道。
5. `KZV03State` 维护跨场景事实旗标；`KZV03Hud` 提供笔记、证据关联和假设；关键线索超过 70 秒 / 120 秒可提示。
6. 若项目里已有第四周测试音频，会**只读加载** `Assets/KongZuo/LMLWeek4/Audio/Placeholder/*.wav`。没有音频时仍可运行文本灰盒。

**重要边界**：这是可操作的叙事灰盒，**尚未经过本机 Unity 编译/Play 实测**，不含正式美术、角色动画、配音、复杂相机叠图和 30–40 分钟用时验证。旧 `LMLWeek4` 的谜题/音频系统源码并未随本包提供，因此没有对它们进行侵入式改写或声称完全接入。

## 安全导入（不要把整个 Unity 工程塞进 Assets）

1. **备份**原桌面 `KongZuo` 工程，关闭 Unity 编辑器。
2. 将压缩包中的 `Assets/KongZuo/V03` 目录复制到**当前工程根目录**的 `Assets/KongZuo/` 之下。最终必须是：

   ```text
   桌面/KongZuo/
     Assets/
       KongZuo/
         Art/                 （原有内容不动）
         Editor/              （原有内容不动）
         LMLWeek4/            （原有内容不动）
         Scenes/              （原有内容不动）
         Scripts/             （原有内容不动）
         V03/                 （本包新增）
           Editor/KZV03SceneBuilder.cs
           Runtime/*.cs
           Docs/*.md
   ```

3. 通过 Unity Hub 打开桌面 `KongZuo`（6000.3.26f1）。等 Console 编译完成且**没有红色错误**。
4. 点击 Unity 顶部菜单：**空座 → V0.3 → 01 生成独立测试场景（保留原场景）**。
5. 生成器不会覆盖已有 `.unity`；如果发现任一 V0.3 场景存在，会拒绝重建以保护修改。新场景在 `Assets/KongZuo/V03/Scenes/`。
6. 生成完成会打开 `V03_00_Prologue.unity`。按 **Play** 试玩。之后章节自动切换。

> 生成器仅往 Build Profiles/Build Settings **追加** V0.3 测试场景，不替换现有团队场景顺序。`ProjectSettings/EditorBuildSettings.asset` 可能因此产生本地改动；合并 Git 前请让主程序确认。

## 操作与剧情流程

- `WASD`：移动；鼠标：视角；`E`：检视/推进文字；`Tab`：调查笔记；`Esc`：释放/锁定鼠标；鼠标左键：重新锁定视角。
- **序章**：清点单 → 推正门 → 办公室电话 → 第一排七号座 → 售票口登记表 → 回到观众厅 → 异常与节目单。
- **第一章**：售票口旧照片 → 观众厅后方偏西对景点（E多次核对灰盒步骤）→ 前厅遗物点交单 → `Tab`笔记点击“关联证据”→ 七号座残响。
- **第二章**：侧台工具箱维修钥匙 → 工作区门 → 化妆间剧照/沈芸与顾兰生活照 → 购票凭证 → 未寄信与旧红线争执 → 服装间许承山纸条、旧戏箱钥匙登记 → 后台东侧工作门 → 清点相机拍门闩 → 未完待续。
- 顾兰空纸套、失票便签、民俗宣传册等为**可选补充**，不会成为独立卡关点。

## 使用现有第4周成果的原则

- `LMLWeek4` 仍是队友协作用功能目录，不能因为 V0.3 改剧情就删除或清空。
- `KZW4_AudioCatalog.asset`、`KZW4AudioManager.cs`、`KZW4PhotoAlignment.cs` 等资源可能已存在于 Git 功能分支，但**本包不知道你目前 Unity 工作区的代码版本**。
- V0.3 先用可独立运行的简化交互，避免与原脚本同名导致 CS0101；音频占位路径以原 `LMLWeek4/Audio/Placeholder` 为可选资源路径。
- 第四周正式接入：可由主程序监听 `KZV03State.Ensure().Changed` 事件（键值见 `KZV03Flag`），将其映射到已有音频管理、正式对景系统和 UI。验证接口后再抽换灰盒，不要双份驱动同一场景。

## 验收与已知限制

**可以验证**：场景是否能生成；关卡能否按门槛推进；角色与证据关系是否与 V0.3 一致；东侧门结束前是否必须拍照；是否不泄露后续真相。

**仍需制作**：1992/2004 双时态灯光与摆设精修、照片真实贴图与相机叠图、角色动作、可听的表演、正式调查笔记 UI、可持续存档、3 名盲测玩家的 30—40 分钟时长校准。

**已知简化**：本包对景使用“粗站位＋三个交互反馈”替代真正照片重合算法；残响使用色块人物/文档和简单移动替代 Timeline 演出；所有文字/位置都是供测试的占位表现。这些不会自动凑出 36 分30秒游戏时长。

## 发现 Unity 报错怎么办？

- **`Assets/KongZuo/V03` 里的脚本红色错误**：在 Console 点击**第一条红色错误**，复制完整信息（文件名/行号）再修。不要使用 `git reset --hard`。
- **找不到“空座/V0.3”菜单**：先检查 Console 是否仍有红色编译错误；Unity 编译失败时无法加载 Editor 菜单。
- **场景生成成功却没有人物/物体**：确认打开的是 `V03_00_Prologue`，而不是旧 `SampleScene`、旧 `00_Bootstrap` 或空白 `Untitled`。
- **没有音乐但流程可走**：核实第四周 WAV 文件是否已完整恢复及 Git LFS 是否拉取。音频不是剧情门槛。
- **原 LMLWeek4 看不见**：检查本地 Git 状态和 `fe7d85c` 历史；切勿把这份补丁压缩包当成完整 Unity 项目。

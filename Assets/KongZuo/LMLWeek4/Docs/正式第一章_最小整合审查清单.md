# 正式第一章：安全最小整合评审（不随包修改原文件）

## 为什么要先审核？

历史文件 `KZStoryDirector.cs` 使用 `KZFlags.Ritual / Photo / Ticket / PuzzleSolved / EchoFinished`；原版关卡的 `KZHud.ShowPuzzle` 是“一排六、七、八座排人”的临时题。策划 V0.4 提出第二套解谜：1992布置照→三地标对位→周明生遗物→返回第7号座触发残响。**不能把旧文件整份覆盖**，否则会丢掉队友已合并的更新。

## 由LML在个人分支进行的最小接线

1. PR-A（纯新增）：合并 `Assets/KongZuo/LMLWeek4/`，只作为独立测试演示；与其他人工作互不冲突。
2. PR-B（经负责剧情和场景的成员同意）：在正式 `02_Chapter01` 中增加新照片、场务记录和参考机位/地标（单场景负责人修改并提交）。优先将新增实体做 Prefab，再由场景负责人实例化。
3. 策划确认是否 **继续让旧座次谜题保留为可玩内容**。如果保留，确保与新的遗物题不会产生两个互相冲突的通关条件；如果替换，旧 `KZSeatPuzzle.cs` 保留源码但场景不再触发，避免拆错其他引用。
4. 将新逻辑成功的“事件”映射到 `KZGameSession.EnsureExists().TryAddFlag(KZFlags.PuzzleSolved)`，而不是让测试场景脚本自行改正式全局旗标。接口集成点应是独立适配器或经过 code review 的小函数。
5. 修改正式 `KZStoryDirector` 中的触发时机：解开遗物题时只提示“回七号座”；返回座椅时检查 `PuzzleSolved && !EchoFinished && !IsBusy`，再进入原有 `PlayEcho()`；保留旧版的恢复逻辑 `Restore2004()`。
6. 和音频组员确定**唯一**的音频经理。将现有剧情里的电话、翻页、锣、年代切换分别调用固定音频 ID，确认已有 AudioManager 后再选择复用还是适配，绝不复制两个音频经理进去。
7. 场景中断、重新读取、错误提交等边界必须在正式三张场景复测。旧原型的 `.meta`、GUID、序章人影和节目单触发均不应失效。
